Melt down your old configs and cast them anew

1 Master folder

Point Crucible at the top-level folder that holds your site sub-folders. Every folder directly containing a .txt or .cfg file becomes one site. Files are read entirely in your browser — nothing is uploaded.

Read-only mode: this browser can’t write files in place, so outputs are delivered as a downloadable .zip instead.

2 Sites & devices

Everything Crucible found, grouped by site. Each site shows its merge options (where a router and switch can collapse into one L3 switch), a per-site spanning-tree root picker, and a collapsible card per device — interfaces, routing/services and hardening, all chosen per device.

3 Global additions

What to collect from each device — interfaces, routing, VRF, DHCP, management — is chosen per device in its card up in Step 2 (pre-ticked with what it already has). The settings here are injected into every output template.

VTP (switches)

Add VTP version 3 to every switch template (routers are skipped). Mode defaults to transparent.

Spanning-tree hardening (switches)

Adds portfast default, portfast bpduguard default and loopguard default to switch templates.

Errdisable recovery (switches)

Auto-recover err-disabled ports (udld, bpduguard, link-flap, port-security, storm-control).

Clock & timezone

Set a consistent timezone and clock on every device (router and switch).

Login / MOTD banner

Inject the same login and MOTD banner on every device.

Secure access

Inject a hardened local admin and SSH login into every output. Generates SHA-256 user & enable secrets, AAA local login, optional type-6 password encryption, and the SSH/VTY commands that make the login work.

4 Template & insertion

By default Crucible writes its own template that matches your selections — you don’t need to supply one. Provide a file only if you want a specific base config.

Using auto-generated template

5 Output naming

Each output is named from the device’s hostname with a fixed .txt extension. Optionally rename — this updates both the filename and the in-config hostname.

6 Computed tag map

A live preview of which marker maps to which block. If you bring your own tag-based template, lay the markers out to match this.

Builds each device template and writes it back beside the source — or downloads a .zip in read-only browsers.
