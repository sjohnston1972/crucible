Crucible

Melt down your old configs and cast them anew

Detecting browser…

1 Master folder

Point Crucible at the top-level folder that holds your site sub-folders. Every folder directly containing a .txt or .cfg file becomes one site. Files are read entirely in your browser — nothing is uploaded.

Read-only mode: this browser can’t write files in place, so outputs are delivered as a downloadable .zip instead.

2 Discovered sites & analysis

The sites and devices Crucible found. Each config is parsed and audited automatically the moment you scan — review what was extracted and the hardening findings per device below.

No folder selected yet.

3 Source files & merge

Tell Crucible how many config files each site should contain, and whether to collapse a site’s devices (e.g. a router + a switch) into a single Layer-3 switch template.

Optional: map each source slot to a filename pattern so collection rules can target it.

4 What to collect

Choose exactly what to pull from each source device into its new template.

Interfaces

Interfaces found in your scan, grouped by device. Tick the ones to carry across and pick All data or IP only for each. Shutdown ports are flagged in red — hover any interface to preview its current config.

Scan a folder in Step 1 and the interfaces found in each device appear here.

IP routing

Select which routing information to migrate. A legacy ip default-gateway is rewritten as a modern default route automatically.

Other data

Carry across these blocks wherever they exist in the source.

Management services

Crucible scans each source for these services and can carry the existing config across. Counts are shown per device in the analysis above.

Secure access

Inject a hardened local admin and SSH login into every output. Generates SHA-256 user & enable secrets, AAA local login, optional type-6 password encryption, and the SSH/VTY commands that make the login work.

5 Template & insertion

By default Crucible writes its own template that matches your selections — you don’t need to supply one. Provide a file only if you want a specific base config.

Using auto-generated template

6 Output naming

Each output is named from the device’s hostname with a fixed .txt extension. Optionally rename — this updates both the filename and the in-config hostname.

7 Computed tag map

A live preview of which marker maps to which block. If you bring your own tag-based template, lay the markers out to match this.

8 Root election & save

Pick which switch is the spanning-tree root for this scan, then save. Outputs are written back beside each source (or downloaded as a .zip in read-only browsers).

The chosen switch is configured as the sole root; the others stand down (root secondary).
