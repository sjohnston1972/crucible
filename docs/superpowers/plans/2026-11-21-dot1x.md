# 802.1X Implementation Check Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an 802.1X settings panel, a batch check of Catalyst 9000 backups that produces changes / full-config files, and an option to bake 802.1X into main-flow switch outputs.

**Architecture:** One pure module, `public/lib/dot1x.js`, owns settings, generation (both styles), the check and the merge. A thin UI module, `public/dot1x-ui.js`, renders the bottom section and reads the settings; `app.js` calls it at init and calls the lib once in `onSave`. The lib reads `parsed.lines` and `parsed.interfaces[].block` itself, so `parser.js` is not changed.

**Tech Stack:** Browser ES modules, no dependencies, `node --test`, esbuild standalone bundle.

**Spec:** `docs/superpowers/specs/2026-11-21-dot1x-design.md`

## Global Constraints

- No new dependencies; lib code must import under Node.
- `parser.js` output shape unchanged; existing tests pass untouched.
- Output files contain only config lines and `!` comments.
- Monitor mode is the default. A port already closed is never opened.
- The two styles are never mixed on one switch.
- After any change under `public/`: `npm run build:standalone`, commit `dist/crucible.html` with it.
- Fixed object names: `DOT1X-MAB-POLICY`, `ACL-PREAUTH`, `DOT1X-IPDT`.

## Review Focus

- A backup with CRLF line endings: the full config keeps CRLF throughout.
- A backup already fully configured by this tool: re-checking reports nothing missing (idempotent).
- A partly-done switch using its own object names (RADIUS server at the same IP, other name): no parallel objects are created.
- A port with a single-value setting already set differently (host mode, control policy): the line is reported, never emitted.
- Settings with required boxes blank: nothing is generated and the missing box is named.

Each of these has a test in Task 1 or Task 2.

### Task 1: `lib/dot1x.js` — settings, scan, port qualification, generators

**Files:** Create `public/lib/dot1x.js`, `test/dot1x.test.js`.

**Produces:**
- `DOT1X_DEFAULTS` — object with the defaults of spec section 6 (`style: "policy"`, `mode: "monitor"`, `order: "dot1x"`, `hostMode: "multi-auth"`, `authPort: 1812`, `acctPort: 1813`, `group: "ISE-RADIUS"`, `server1Name: "ISE-1"`, `server2Name: "ISE-2"`, `coa: true`, `txPeriod: 10`, `reauth: true`, `criticalVoice: true`, others `""`).
- `normalizeSettings(raw) -> settings`, `validateSettings(settings) -> string[]` (empty = valid; messages name the box).
- `scanDot1x(parsed) -> scan` — what the config already has (see spec section 9), including `supported` (false when the `version` line is below 16) and `style` (`"classic" | "policy" | null`).
- `qualifyingPorts(parsed, settings) -> { ports: [{ name, normName, description }], skipped: [{ normName, word }] }` per spec section 7.
- `globalLines(settings, names)` and `portLines(settings, names)` — the reference command sets of spec section 8, corrected against Cisco documentation.

Steps: tests first for defaults/validation, port qualification (access, trunk, channel member, routed, skip words, shut-down), scan (style detection, version guard, server-by-IP), and generator output for both styles × three modes × optional settings; run red; implement; run green; commit.

### Task 2: `lib/dot1x.js` — check, changes file, merge

**Files:** Modify `public/lib/dot1x.js`, `test/dot1x.test.js`.

**Produces:**
- `checkDot1x(parsed, settings, opts = { ports: Set<normName> | null }) -> { supported, style, conflict, items: [{ id, label, state, detail }], ports: [{ name, normName, state, add: string[], remove: string[], differs: string[] }], global: string[], warnings: string[], counts: { globalsPresent, globalsTotal, portsDone, portsTotal }, complete }`.
- `changesText(check, { hostname, settings }) -> string`.
- `applyDot1x(text, check) -> { content, added }` — globals under `! ==== 802.1X ====` via `insertAfterDomainName`, port lines merged into existing interface blocks, CRLF preserved.
- `stripPortDot1x(text) -> { content, ports: string[] }` and `addDot1xToOutput(text, settings) -> { content, warnings }` for the main flow.

Steps: tests first for the four states, name reuse, per-line `differs`, closed-port guard, style conflict, `aaa new-model` warning, idempotence, CRLF, strip-and-regenerate; red; implement; green; commit.

### Task 3: Bottom section UI

**Files:** Create `public/dot1x-ui.js`; modify `public/index.html` (new card after `#step-verify`), `public/styles.css`, `public/app.js` (import + `initDot1xSection({...helpers})` in `init`).

**Produces:** `initDot1xSection(deps)`, `readDot1xSettings()`.

Behaviour per spec section 10: settings panel, folder picker, tick list (routers unticked), Check, per-switch cards with port ticks and "View changes", output-type ticks, zip download (`crucible-dot1x.zip`, `<name>_dot1x_changes.txt` / `<name>_dot1x_full.txt`), stale marker when a setting changes after a check.

Verify: `npm test`, `npm run build:standalone`, then drive the page in a browser with a folder of test backups. Commit.

### Task 4: Main flow

**Files:** Modify `public/index.html` (Global additions entry), `public/app.js` (`readGlobalConfig`, `onSave`), `test/integration.test.js` or `test/dot1x.test.js`.

In `onSave`: block with a named message when the tick is on and `validateSettings` fails; after `removeDuplicateLines`, for switch units call `addDot1xToOutput` and push its warnings.

Test: a 2960-style config with classic 802.1X port lines through `addDot1xToOutput` with policy style yields the global block, policy port lines on access ports only, and no legacy port lines.

Verify: `npm test`, `npm run build:standalone`. Commit, push.
